# Untrusted checkouts

A Foreign PR is code and text anyone could have written. Fern fetches it, checks it out, has an agent read it and shows what that agent wrote ([ADR 0010](adr/0010-foreign-pr-walkthroughs-are-written-by-a-fresh-read-only-agent.md)). Each way the PR could act through that is a **vector**. A Foreign PR diff keeps every defence below in place, and a new way in gets its own entry.

Two folders matter. The **Project's checkout** is the developer's own: its hooks, config and attributes are trusted. The **PR's worktree** (`PrWorktrees`, under `prs/`) holds the PR's files, so anything git or Claude Code reads from it is the PR's say.

- **Git hooks via `core.hooksPath`.** A relative path, as husky sets, resolves among the PR's own files. `packages/server/src/pullrequest/PrWorktrees.ts`: `NO_HOOKS` (`core.hooksPath=/dev/null`), added by `guard` to every call through `run`, and `PrWorktrees.git` for the rest of Fern's Foreign PR code. `scripts/check-foreign-git.ts` (run by `pnpm lint`) refuses any other git call in `pullrequest/` and `walkthrough/`.
- **`reference-transaction` hooks.** They fire on any ref update, including the HEAD moves of `worktree add` and `checkout --detach`. Ref updates in the PR's worktree go through `PrWorktrees.run`, so `NO_HOOKS` covers them. Ref updates on the PR's commits happen in the Project's checkout, with the developer's own hooks: `CodeHost.fetchPullRequest` (`packages/server/src/codehost/CodeHost.ts`) and `snapshots.pin` in `Walkthroughs.prepareForeign` (`packages/server/src/walkthrough/Walkthroughs.ts`), which reads and pins with `change.project`, never `change.cwd`.
- **`.gitattributes` filters.** The PR picks which of the developer's filters (git-lfs's, say) run on which file during checkout or `status`. `PrWorktrees.ts` `guard`: blanks `smudge`, `clean` and `process`, and sets `required=false`, for every `filter.*` the Project's config names. Diffs are read with `diff-tree` in the Project's checkout (`Snapshots.diff`, with `--no-ext-diff`).
- **`.claude/settings.json` hooks**, and the PR's `CLAUDE.md` and MCP servers, read by the Walkthrough writer running in its worktree. `packages/server/src/walkthrough/WalkthroughWriter.ts` `foreignOptions`: `settingSources: []`, `strictMcpConfig: true`, `mcpServers: {}`, tools and `allowedTools` limited to `READ_ONLY_TOOLS` (Read, Grep, Glob) with `permissionMode: "dontAsk"`, and the `insideCheckout` PreToolUse hook denying a path or glob outside the worktree, links followed.
- **Remote images in rendered markdown.** Loading one tells the author's server who read the PR, and when. `packages/ui/src/Markdown.tsx` `images={false}` renders each image as `ImageLeftOut`. `apps/web/src/review/SectionPane.tsx` sets it for any Walkthrough with a `foreignPr`. On GitHub, `packages/server/src/pullrequest/review.ts` `code` posts the writer's text and the PR's paths as inline code, so nothing in them renders as a link, image or mention.
- **Cross-repo issue reads.** A PR's "closes" link can name an issue only the developer can see, which would then reach the writer. `CodeHost.pullRequest` (`CodeHost.ts`) keeps `closes` only for an issue on the PR's own repo; `CodeHost.issue` is called only with that.
- **Untrusted text in `gh` arguments.** A note, a title or a path that reads as a flag. `CodeHost.postReview` sends the review as JSON on stdin (`gh api … --input -`). Numbers and branch names are checked first (`Number.isInteger`, `BranchName` in `fetchPullRequest`).

Out of scope: Try it (`PullRequests.tryIt`) checks the PR out for the developer to run, in a Terminal of its own. Whatever runs there runs at the developer's say.
